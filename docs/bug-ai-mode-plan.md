# Bug AI Mode 実装計画

2026-09-11 / 設計のみ。アプリコードの実装、OpenCodeへの推論リクエスト、テスト・ビルド・実画面検証は行っていない。

## 1. 実現する動作

AI ModeがONなら、虫が齧る前にローカルOpenCodeへ変更案を依頼する。変更が確定するまでコードは消さず、虫に🧠を表示する。返答と対象コードを検証してから齧り、変更後コードをうんこに保持する。触れると、その確定済みコードを戻す。

変更種類はアプリ側で1回だけ抽選する。

| 抽選範囲 | 確率 | 種類 | 例 |
| --- | --- | --- | --- |
| `r < 0.3` | 30% | 部分的な関数変更 | `fast 2` → `slow 2` |
| `0.3 <= r < 0.6` | 30% | 数値・mini notation変更 | `# speed 1` → `# speed 1.5`、`"bd sd"` → `"bd*2 [sd ~]"` |
| `0.6 <= r` | 40% | 構造の突然変異 | `s "bd sd"` → `sometimes (fast 2) (s "bd sd")` |

`r = Math.random()` とする。カテゴリの決定をモデルに任せない。失敗時も同じ試行でカテゴリを引き直さない。30/30/40は試行の確率であり、10回中必ず3/3/4という割当ではない。検証で不採用になる結果があるため、実際に適用された変更の比率は一致しない。

AI Modeでは既存の `mutateTidalText` と復元時の5%構造変異を呼ばない。AIが考えた変更に機械的変更を二重適用しない。

| --- | --- | --- |
| Show living code bug | 現状維持 | 常時 |
| Reel mode | 現状維持 | Show living code bugがON |

モデル欄は `provider/model` のテキスト入力とし、取得できたモデル一覧を候補表示する。入力途中の文字列は送信に使わず、確定した有効値を保存する。存在しないモデルなら項目の近くに理由を表示し、別モデルへ自動で切り替えない。

AIとReelは併用できる。Reelは咀嚼2秒と排泄後の再採食に作用する。AIの30/30/40は変えず、Reel時のプロンプトには同じ制約内で変化を強める指示を加える。推論時間は咀嚼時間とは別なので、AI+Reelでも全工程が2秒になるわけではない。

## 3. OpenCode接続

現在のローカルCLIは `1.18.30`。実体は `/Users/jumang4423/.opencode/bin/opencode`。`opencode models opencode` に指定のデフォルトモデルが存在することを確認済み。実際の推論成功・structured output対応・残量は未確認。

通信は `Editor/Bug → preload IPC → Electron main → OpenCode SDK → ローカルOpenCode server → 選択プロバイダ` とする。SDKとプロセス管理をmain側に置き、rendererへ認証情報や任意HTTP/シェル実行機能を公開しない。

推奨はAI Modeの有効化時に、アプリ所有の `opencode serve --hostname 127.0.0.1 --port 0 --pure` を必要なときだけ起動する方式。ランダムな空きポートを使い、アプリ所有のプロセスだけ終了時に停止する。既存のユーザーTUIやそのセッションは操作しない。起動中Promiseを共有し、複数の虫が同時にサーバーを立ち上げない。

ローカルOpenCodeと同じユーザー環境・provider認証を使う。これはローカルでモデルを実行する意味ではなく、現在OpenCodeで使っているプロバイダの利用枠を使う意味。利用残量が取得できないときに独自のquota残量を表示しない。認証ファイルをアプリにコピーしない。

アプリ用作業ディレクトリと実行時の専用agent設定を使う。既存のprovider設定を利用しながら、Bash・ファイル編集・MCP・Web・他agent呼び出しなどは無効化する。コードは明示的に送った文字列だけで判断させる。structured outputに必要な `StructuredOutput` の経路は残す。権限ルールの詳細は固定したCLI/SDK版で確認する。

Loopbackサーバーにもアプリ生成の一時パスワードを設定し、mainだけが保持する。ユーザーのOpenCode設定ファイルは書き換えない。

1リクエストにつきアプリ用の独立セッションを作り、成功・失敗・キャンセル後にアプリが作ったセッションだけ削除する。以前の食事の会話履歴を次へ渡さない。モデルはリクエストごとに `providerID` / `modelID` を明示し、OpenCodeの全体デフォルトを変更しない。

SDK公式例は `session.prompt` の `format: { type: "json_schema", schema, retryCount }` と `info.structured_output` を使う。一方で同じページのAPI表には `outputFormat` 表記もあるため、実装時はCLIと対応するSDK版を固定し、型定義とサーバーのOpenAPIで最終契約を確定する。

参照: [Server](https://dev.opencode.ai/docs/server/)、[SDK / Structured Output](https://dev.opencode.ai/docs/sdk/#structured-output)、[Config](https://dev.opencode.ai/docs/config/)、[Permissions](https://dev.opencode.ai/docs/permissions/)。

## 4. 齧るまでの状態遷移

1. 空腹の虫がAI向け候補を探し、変更カテゴリを抽選する。
2. そのカテゴリに対応する編集範囲と文脈を固定し、対象パターンを予約する。
3. 食べ場所まで移動する。問い合わせ待ちの間も他の虫・エディタの描画は止めない。
4. 口が届いたら `thinking` に入り、移動を止めて🧠を表示し、1回だけリクエストする。まだ齧り始めず、コードも消さない。
5. 成功したらJSON・変更内容・現在の文書を検証する。
6. 通過した場合だけ `chewing` に移り、🧠から既存の🍙表示へ切り替える。
7. 通常3秒 / Reel2秒の咀嚼終了時に、もう一度対象の一致を確認して食べる。
8. AIの `newText` を保持したうんこを生成する。復元時にAIを再呼び出さない。

失敗ならその回は食べず、🧠を消して移動へ戻る。AI失敗を理由に機械的変更へ切り替えない。

`thinking` は独立した非同期状態として扱う。描画の毎フレーム処理内で `await` しない。カーソル接近で逃げる場合はリクエストをキャンセルし、現在の「逃げる」優先を維持する。虫のOFF・タブの非表示/破棄・AI OFF・モデル変更時も、まだ食べていないリクエストを取り消す。

食べ終わったうんこは生成時の変更案を保持する。モードやモデルを後から変えても、別方式で再変異させない。

## 5. AIに渡す範囲

現在は行単位の関数名・数値を正規表現で拾い、文字列をマスクしている。その処理ではmini notationと構造変更を扱えないため、AI専用の候補抽出を追加する。

アプリが「変更可能な範囲」と「読むための周辺文脈」を分けて渡す。AIが任意のファイルや行を選ぶ仕様にはしない。

| カテゴリ | 編集可能範囲 | 読む文脈 |
| --- | --- | --- |
| 関数 | 関数名または必要な引数を含む部分式 | 対応するTidalパターン |
| 数値・mini notation | 数値トークン、modifier、または引用符を含む文字列全体 | 関数名・コントロール名・パターン |
| 突然変異 | 完結したControlPattern式 | 対応するd番号と周辺コントロール |

最初の実装は、空行で区切られた1行の `dN $ ...` で範囲が確定できる式を対象にする提案。`let`、ユーザー定義の複雑な宣言、複数行の`stack`などはスキップし、部分的に誤認して齧らない。複数行対応は同じ契約で候補抽出を拡張する次段階とする。

AI Modeでは `s "bd sd"` だけの行も候補になる。既存の機械的変更候補がないことを理由に、mini notation / 構造変異が発生しなくならないようにする。

`dN`、コメント、保護対象コントロールは編集可能範囲から外す。特に `# legato ...` は値だけでなく節を保持する。保護節を横断せずに構造変更できる範囲を切り出せない場合は、その場所を候補にしない。

構造変更では式全体が食べる範囲になる場合がある。単語だけの場合より大きくコードが消えるので、実際に消す範囲全体に咀嚼表示を付ける。現行のテキスト除去→うんこから復元の演出は維持する。

## 6. JSON契約とプロンプト

モデルに返させる内容は以下だけ。

```json
{
  "oldText": "s \"bd sd\"",
  "newText": "sometimes (fast 2) (s \"bd sd\")"
}
```

JSON Schemaではobject、両フィールド必須、string、`additionalProperties: false`、長さ上限を指定する。structured outputのリトライは初期値0とし、失敗時の隠れた追加問い合わせを抑える。

`oldText` はアプリが許可した元文字列との完全一致が必須。AIが位置情報を返したり、全文から同じ文字列を検索して置換したりしない。`newText === oldText` は変更なしとして終了する。

アプリ内部では `requestId / documentId / editorGeneration / agentId / category / model / trackedRange / originalText / contextFingerprint` を保持する。これらの整合性をAIに判断させない。

プロンプトは共通ルール＋カテゴリ固有指示＋読み取り専用文脈＋編集対象の4部分にする。コード中のコメントや文字列は入力データであり指示ではないと明示する。

共通ルール:

- TidalCyclesの式として、提供された編集対象に対する1つの置換を返す。
- `legato` と既存ブラックリストの `gain / n / orbit / begin / end` を変更・削除・追加しない。
- 負の数を新しく導入しない。倍率・回数でゼロが無効なところには正の値を使う。
- 確率やpan等は0〜1、個数は整数など、引数ごとの制約を守る。
- 既存のサンプル名とサンプル番号を保持し、mini notationではリズム・反復・休符・グループ等を変更する。
- コードを無音化する指示、IO、ファイル操作、GHCiコマンド、import、宣言を生成しない。
- 与えたTidal関数候補と文脈の範囲で変更する。

カテゴリ固有指示:

- 関数変更: 数値と文字列を保持し、引数の型が適合する関数に局所的に変更する。
- 数値・mini notation変更: 関数名とコントロール名を保持し、許可した数値または文字列の内容を変更する。
- 突然変異: 音の素材を保持し、変換関数によるラップや構造の組み替えを行う。式の増大には上限を設ける。

mini notationの記号と負数を区別する。単純に `-` という文字をすべて禁止する実装にはしない。

## 7. 返答の検証

Structured Outputが保証するのはJSONの形であり、Tidalとしての正しさや音が出ることではない。検証はAIとは別の処理にする。

採用前に以下を確認する。

1. JSON契約、文字数上限、完全一致するoldText、実際の差分があること。
2. 許可範囲外の変更がないこと。保護節・d番号・サンプル識別子が保持されていること。
3. カテゴリに沿っていること。例えば数値カテゴリで関数名まで変えていたら不採用。
4. 文字列・括弧の整合、負数の新規導入、引数の既知範囲、禁止された言語要素を検出すること。
5. 置換を仮適用したパターン全体として構文・型を確認すること。

現在のエディタはHaskellのシンタックスハイライト用StreamLanguageであり、型検査できるASTパーサーはない。したがって、5は既存の正規表現検査だけで成功扱いにしない。

推奨は演奏用GHCiとは別の検証用プロセスで、許可した式だけを型照会すること。演奏開始やOSC送信を行うBootTidal全体は検証プロセスで実行しない。必要なTidal importと純粋な定義だけを用意する。独自関数の型が再現できない対象は不採用とする。検証プロセスにも時間制限を付ける。

mini notationはHaskell上では文字列なので型検査だけでは中身の不正を検出できない。許可する記法を絞った構文検査を別に用意し、遅延評価時のエラーまで完全に排除できるとは扱わない。生のAI出力を「試しに演奏」して検証することはしない。

## 8. 編集との競合・うんこの無効化

対象範囲と文脈はCodeMirrorの変更マッピングで追跡する。別の行への挿入で座標だけ変わった場合は追従し、依存するパターンをユーザーが編集した場合は無効化する。同じ文字に戻した場合も、古い非同期結果は再採用しない。

AI問い合わせ中・返答後の移動中・咀嚼中のどこでも、対象が変更されたらキャンセルする。キャンセル後の遅い返答はrequestIdとgenerationの不一致で捨てる。

食べた後の編集は既存の0.5秒フェードに接続する。AIの構造変更では影響が部分トークンより広いため、復元条件は差し込み位置だけでなく、依存していたパターンの一致で判断する。触れる瞬間にも再検証し、フェード開始前の1フレームでも古いコードを戻さない。

同じパターンは問い合わせ開始から復元・破棄まで1匹が予約する。他の虫にはそのパターンを候補として出さない。現在の `bugDocumentChange` は虫由来の変更を一律にユーザー編集から除外するため、この予約なしでは虫同士の変更が衝突する。

食べた変更には `source: "mechanical" | "ai"` と確定済み変更案を持たせる。AI由来のうんこの復元時は既存の機械的な構造変異を行わない。

## 9. 失敗・利用枠・後始末

初期値はアプリ全体で推論1件まで。同じ虫は1件だけ。待ち行列を際限なく作らず、実行枠がない虫は普段どおり移動する。

推論の時間制限は60秒、通信エラー後は30秒の待機を初期案とする。時間切れはHTTPのAbortだけでなくOpenCodeの当該セッションabortも呼ぶ。返答破棄・🧠解除・予約解除・セッション後始末は成功/失敗の共通finally経路にまとめる。

認証エラー・モデル不在・利用枠の制限ではAI採食を停止し、設定に理由と再試行操作を出す。別の有料モデルへの自動切替や連続した自動再問い合わせはしない。ユーザーのモデル変更や明示的な再試行で再開する。

残量がAPIで取れない場合は「残り何%」を推測せず、制限中という状態だけ示す。ログはrequestId、カテゴリ、モデル、処理時間、採否理由を中心とし、認証情報を含めない。

指定モデルはローカル一覧と公式Zenのモデル表で確認できた。ローカルserverを経由しても入力は選択プロバイダへ送られるため、送信するコードは対象パターンと必要最小限の文脈に限定する。指定のContributorモデルには入力・出力の学習利用条件が記載されている。[OpenCode Zen](https://dev.opencode.ai/docs/zen/)

## 11. 実装後に確認する条件

過去の「テスト・ビルド・実画面検証を行わない」指定を維持する。以下は確認項目の計画であり、実行済みではない。実行検証を行う場合は、その指定が変更されてから行う。

- AI OFFでは既存動作のまま。Show OFFではAI/Reel/モデル入力がdisabled。
- 0.3と0.6の境界でカテゴリが正しく分かれ、1試行で1回だけ抽選される。
- 推論前にコードが消えず、🧠が成功・失敗・取消のすべてで消える。
- モデル変更、タブ切替、エディタ再読み込み、カーソル接近、編集後に古い結果が適用されない。
- legato等の保護、負数、mini notationの記号、重複するoldTextを正しく扱う。
- AIの確定結果が機械的な変異で上書きされない。
- 編集で無効になったうんこが0.5秒でフェードし、触ってもコードが戻らない。
- quota/JSON不正/タイムアウトで連続リクエストや別モデルへの切替が発生しない。
- アプリ終了・renderer破棄時に予約/Promise/セッション/所有プロセスが残らない。
- 実際のモデルでstructured outputが返ること、型検証とmini notation検査の実用範囲、推論時間を別途確認する。
